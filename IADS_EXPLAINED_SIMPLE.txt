WHAT IS "composite_with_iads"?
═══════════════════════════════════════════════════════════════════════════════

It's a USB configuration flag that affects how your device IDENTIFIES itself to
the operating system.

IADS = "Interface Association Descriptor"


REAL-WORLD ANALOGY
═══════════════════════════════════════════════════════════════════════════════

Imagine a Swiss Army knife with 4 tools:
  1. A blade (controller)
  2. A corkscrew (audio interface)
  3. A bottle opener (plugin module)
  4. A flashlight (security)

COMPOSITE_WITH_IADS = FALSE:
  → Operating system sees: "4 separate tools"
  → Windows: "What are these? Should I load 4 different drivers?"
  → Result: Confusion, may not work correctly

COMPOSITE_WITH_IADS = TRUE:
  → Operating system sees: "1 Swiss Army knife with 4 tools"
  → Windows: "Ah! This is an Xbox 360 controller! Load THE Xbox driver for all!"
  → Result: Perfect - everything works as one unit


YOUR DEVICE'S 4 INTERFACES
═══════════════════════════════════════════════════════════════════════════════

When composite_with_iads = true, Windows sees:

    ┌─── Xbox 360 Controller (Grouped with IAD) ───┐
    │                                               │
    ├─ Interface 0: Controller (button/stick data)  │
    │  ├─ IN endpoint  → Send controller state      │
    │  └─ OUT endpoint → Receive rumble commands    │
    │                                               │
    ├─ Interface 1: Audio (unused, dummy)           │
    │  ├─ IN endpoint  → (placeholder)              │
    │  └─ OUT endpoint → (placeholder)              │
    │                                               │
    ├─ Interface 2: Plugin (unused, dummy)          │
    │  └─ IN endpoint  → (placeholder)              │
    │                                               │
    └─ Interface 3: Security (no endpoints)         │
       └─ Vendor descriptor (XSM3 string)           │
    
    THE MAGIC: IAD (Interface Association Descriptor)
    tells Windows "these 4 are one device"


WITHOUT IAD (composite_with_iads = false)
═══════════════════════════════════════════════════════════════════════════════

Windows sees:

    Interface 0: Controller
    Interface 1: Audio
    Interface 2: Plugin
    Interface 3: Security
    
    Windows: "Uh... I don't see how these connect"
    Result: Device may not work correctly


THE PROBLEM: I2C CONFLICT
═══════════════════════════════════════════════════════════════════════════════

When composite_with_iads = true:

  USB generates MANY interrupts (1,000-2,000 per second)
         ↓
  These interrupts happen every 0.5-1.0 millisecond
         ↓
  I2C clock needs precise 10 microsecond timing
         ↓
  USB interrupts steal CPU time from I2C
         ↓
  I2C clock pulses get missed/delayed
         ↓
  OLED screen fails to initialize

WHY YOUR DEVICE USES IT
═══════════════════════════════════════════════════════════════════════════════

You're EMULATING a genuine Xbox 360 controller.

A real Xbox 360 controller HAS:
  ✓ 4 interfaces
  ✓ Uses IAD to tell Windows they're all part of one controller
  ✓ Uses class codes 0xFF (vendor-specific)

Your code (line 230):
  let mut function = builder.function(0xFF, 0xFF, 0xFF);
                                     └─ vendor-specific class

Then creates 4 interfaces and groups them with IAD.

This makes Windows load the official Xbox 360 controller driver for your
emulated device, which is what you want!

THREE SOLUTIONS
═══════════════════════════════════════════════════════════════════════════════

1. RECOMMENDED: Set to false
   Change line 216:
      usb_config.composite_with_iads = false;
   
   Result: Display works, but Windows won't auto-load Xbox driver


2. TRY: Increase I2C frequency
   Add at line 196:
      let i2c = I2c::new(
          peripherals.I2C0,
          I2cConfig::default()
              .with_frequency(Rate::new(400_000))  // ← 400 kHz
      )
   
   Result: May work if OLED supports high speed I2C


3. WORKAROUND: Disable display
   Comment out line 199:
      // spawner.spawn(display_task(i2c, stack).unwrap());
   
   Result: USB works perfectly, but no screen feedback


BOTTOM LINE
═══════════════════════════════════════════════════════════════════════════════

composite_with_iads tells the OS:
  "These 4 USB interfaces are grouped together as one Xbox controller"

✓ This is ESSENTIAL for Windows to recognize it properly
✗ This causes SO MANY USB interrupts that I2C timing breaks

It's a hardware limitation of the ESP32-S3: not enough interrupt capacity
to handle both high-frequency USB and time-sensitive I2C simultaneously.
