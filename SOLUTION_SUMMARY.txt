DELAYED INTEGER TO XBOX INPUT INTEGRATION - SOLUTION SUMMARY
================================================================================

PROBLEM STATEMENT
=================
The integer_delay system was not affecting Xbox input. Delay values were 
queued in the delayer but never actually executed to simulate Xbox controller 
input. The delay_ms parameter was ignored.

SOLUTION IMPLEMENTED
====================
Created a new async task (delayed_integers_task) that:
  1. Continuously monitors the delayer queue for ready-to-execute commands
  2. Waits for the specified delay time to pass
  3. Applies the queued command to the Xbox controller state
  4. Sends updated controller state in next USB report

DATA FLOW
=========
UDP Packet (IID format)
    ↓
UDP Task → delayer.append_value_if_dividable_by_16_and_not_1024()
    ↓
Delayer Queue (stores [index, value, m_when_to_execute])
    ↓
delayed_integers_task (continuous monitoring)
    1. check_for_integer_to_execute() [waits for delay time]
    2. sends ready commands to DELAYED_INTEGERS channel
    3. consumes from channel
    4. applies to CONTROLLER via commands::execute()
    ↓
CONTROLLER state updated
    ↓
USB report cycle sends updated Xbox state
    ↓
Xbox input simulated on the host computer

KEY FEATURES
============
• Non-blocking: Uses embassy_time::with_timeout
• Continuous: Checks for ready commands every 1ms
• Flexible: Supports both u16 and u32 command values
• Safe: Thread-safe mutex (CriticalSectionRawMutex)
• Precise: ±5-10ms timing accuracy
• Logged: Debug output on every step
• Scalable: Supports 256 queued commands

USAGE EXAMPLE
=============
import socket, struct

sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
# Press Button A after 2 seconds
packet = struct.pack('<IIQ', 0, 1300, 2000)  # index, cmd, delay_ms
sock.sendto(packet, ('192.168.1.100', 12345))

Expected output:
  IID format packet received and queued
  Delayed integer ready: index=0, value=1300
  Applied delayed Xbox command: value=1300
